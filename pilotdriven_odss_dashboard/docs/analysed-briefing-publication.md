# Analysed flight briefing publication

The default combined download follows the supplied SQ605 REV1 layout in nine landscape pages. `operational_format.py` measures card content at a fixed readable size and fails publication on overflow. It never truncates a source or creates continuation pages. Surface figures use validated supplied geometry; missing geometry stays missing.

`airport_pdf_analysis.py` projects the existing airport panels into bounded flight-time consequences. It uses each airport role separately, reuses the existing dated runway analysis and never promotes unresolved applicability or a component outage into an airport/approach closure. Original airport cards and Show full NOTAM remain in the app.

`concise_pdf_gate.py` checks the nine page owners, analysed lines and inline IDs, no raw Item E, no source attachment, no repeated per-item review label, and working internal links. The corpus runner also checks physical overlap and parsed input checksums. The app publication gate compares the same consequence/ID model while retaining full dashboard-source checks.

The explicit internal audit renderer remains for historical regression and the pinned REV3 raster contract; no service download requests its appendix. Historical drawing tests are in `test_reference_brief_composition.py`. Production format acceptance is in `test_combined_brief.py`; historical tests alone cannot certify a current download.

The v46 report cache revision invalidates older combined PDFs. A release must pass the guarded script and then fresh signed-in browser/download checks. Local fixtures and the private audit are not production proof.

## Reference-format conformance

David sent four reference Flight Briefings on 9 Sep 2026 and asked "So you have to check and make sure the memory losses and standard established does not degenerate. How do you ensure that???". `scripts/check_reference_conformance.py` is that check. It runs the real analysis on private-corpus OFPs, renders each briefing through the exact production download call (`render_combined_briefing` with no audit appendix), and compares the physical PDF with `tests/boss_reference_format_manifest.json`.

That manifest is minted from his own files by `scripts/mint_reference_conformance.py` and records the SHA-256 of each. `PILOTDRIVEN_BOSS_REFERENCE_DIR` must hold them for every deployment: the gate re-derives the structure from the primary reference and refuses a manifest that has been edited to match whatever we happen to draw. The structural floors this codebase adds on top of his document - the ribbon on every page, the active ribbon item tracking the page, a minimum of three timeline stops, a drawn route panel - live in `contract_extensions` with the reason each is ours, so they are never mistaken for his ruling. The same conformance check runs per case inside the mandatory corpus runner.

Every label the manifest pins is compared whole. An earlier revision of the gate compared only the first word of each page-1 column field, which accepted his `TAF TEMPO` shrinking to a bare `TAF` and reported `valid=True` over a real disagreement with his file. Binding rule for this round: where his reference briefing and our render disagree, his reference wins, so the page-1 destination column now publishes his `TAF TEMPO` field, holding the source TAF's temporary group verbatim; a TAF with no TEMPO group says so rather than printing an empty forecast, and the departure column keeps his plain `TAF`. The tile-heading check stays a first-word match combined with the whole label being published on the page, because our renderer wraps `WEATHER / HAZARDS` onto two lines where his fits it on one and this gate does not pin line breaking.

The SQ214 REV3 raster gate is *not* this gate. It is the deterministic-renderer canary for the internal lossless audit composition; its manifest declares `artefact: internal-lossless-audit-composition`, and it refuses any candidate short enough to be the pilot-facing publication.

The exact historical raster gate re-renders the SHA-pinned private analysis in `tests/rev3_replay_input_manifest.json` with the current renderer and original source PDF. Store `SQ214_REV3_v16_analysis.json` beside the approved reference, or set `PILOTDRIVEN_REV3_ANALYSIS_JSON`. Missing or changed input fails the release. The original reference PDF, raster checksums and zero-difference thresholds remain unchanged. This isolates historical layout from changing NOAA responses. The full source-to-PDF corpus still performs fresh analysis and remains mandatory before the replay; its output is never replaced by a historical capture.

`analysed_briefing_map.py` draws held CFP polygons, the existing matched live hazard areas (including polygon holes), OFP VWS events, and time-matched cyclone centres on the filed route. IDs join each marker to a readable key. A volcano point is never turned into an ash area. The map distinguishes passage validity and matched live route/time/level evidence; it does not infer weather clearance. The complete source level profile is printed, including a single-level profile. Passage screening uses entered ATOT where held and checks both ends of validity.

`analysed_briefing_content.py` publishes an existing cyclone centre-distance result only within this flight's time window. Without that evidence it names the missing flight-window coverage, rather than copying unrelated current movement. Deferred effects come from explicit typed source constraints, never the MEL number: for example, a requested dry-ice uplift becomes a catering action without inventing a quantity, MEL allowance or release decision. Unresolved technical effects remain named in the closing record. Closing actions are numbered and derived from unresolved source states, affected airports and route segments. Complete/non-applicable topics and zero-count boilerplate are omitted.

Publication checks also bind the level profile, cyclone consequence, hazard key and deferred consequences to their owning PDF pages. Section footers must name their section and unsupported replacement glyphs are rejected. These are additional gates; the airport analysis in the app and historical audit renderer remain intact.

The shared `deferred_pdf_analysis` model holds each consequence with its declared references, existing gate IDs and source-item indices. Each source segment is analysed before grouping identical consequences: a recognised action cannot hide another defect sharing its MEL number. The app parity check requires each analysed line on page 8 and accounts for every gate/source-item pair. Distinct declarations may share an OFP source row, so their gate IDs remain separate. Original descriptions and remarks remain covered by the dashboard checks; they are not demanded back into the concise PDF.
